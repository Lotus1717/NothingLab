# 废话预言家 · 产品评估摘要

**文档类型**：内部产品文档（Product Owner 评估）  
**评估日期**：2026-06-07  
**版本参考**：1.0.0（`lib/config/app_version.dart`，与 `pubspec.yaml` 一致）

---

## 产品定位与价值主张

**传感器 + AI 无厘头预言**，以 **俏皮神谕（Playful Oracle）** 为视觉与叙事 IP。

用户通过戳慵懒小猫（LazyCat）触发预言，手机传感器数据（电量、步数、音量、环境亮度、运动状态等）成为「预言素材」，输出轻松、可分享的中文废话。情感化 UI（粉珊瑚 + 薄荷绿渐变、打字机预言卡、Oracle 背景）强化「小仪式」感，而非工具或占卜严肃感。

**当前价值主张（1.0.0）**：开箱即用——默认 **DeepSeek 云端**生成高质量废话，无需用户配置 API Key；配额用尽或离线时静默降级到内置模板库，保证「戳猫必有回应」。

## 目标用户与使用场景

| 用户画像 | 典型场景 |
|----------|----------|
| 喜欢轻松梗、无厘头内容的年轻用户 | 无聊时戳猫听一句废话，截图或分享图发给朋友 |
| 对「手机数据算命」好奇的尝鲜者 | 看传感器读数如何被编进预言，产生会心一笑 |
| 社交传播驱动型用户 | 收藏喜欢的预言，用 `ProphecyShareCard` 生成分享图 |

**非目标用户**：严肃占卜/决策参考、需要历史追溯与跨设备同步的重度用户。

## 核心体验评估

### 优点

| 维度 | 说明 |
|------|------|
| **闭环清晰** | 首页 LazyCat → 传感器条 → 预言卡 → 收藏/分享图，路径短、反馈明确 |
| **零配置云端** | 默认 DeepSeek，用户无需在设置里填 Key；降低首次使用摩擦 |
| **多引擎降级** | 苹果本地 / MLX 千问（iOS 内部保留）/ DeepSeek / 模板库；失败或超限自动回退模板库 |
| **情感化 UI** | Playful Oracle 主题、LazyCat 动效（加载时耳朵竖起 + 淡金光）、动物 loading 文案、打字机出字 |
| **分享图** | `ProphecyShareCard` 生成图片 + 系统分享，利于社交传播 |
| **首页引擎角标** | 标题旁 `StatusChip` 展示计划使用的生成途径（DeepSeek / 模板库等），轻量透明 |
| **叙事已对齐** | README、设置页脚注与真实交互一致（戳猫、收藏、构建时 bundled 千问） |

### 不足

1. **无 onboarding**：首次打开未引导权限、传感器真/模含义、每日配额与降级行为  
2. **analytics 仅本地**：已记录生成次数与收藏率（`AnalyticsService`），尚未上报服务端、无引擎分布与分享转化  
3. **Android 能力落差**：无 MLX 千问与苹果本地；主要依赖 DeepSeek + 模板库，需在用户预期层面持续说明（设置页脚注已有一句，仍偏隐晦）  
4. **引擎切换已隐藏**：设置页不再暴露引擎选择与 Key 输入——简化 UX，但 power user 与调试不便；内部途径（千问/苹果本地）仅代码层保留  
5. **角标为「计划途径」非「上次实际」**：`displayEngine` 反映 `preferredEngine`，不反映配额用尽后的静默降级；用户可能看到「DeepSeek」角标却收到模板库内容  
6. **配额计数时机**：`recordCall()` 在 API 请求发出前即记账，失败调用也消耗当日额度

## 差异化与竞品对比

| 维度 | 废话预言家 | 通用 AI 聊天 / 运势类 App |
|------|------------|---------------------------|
| 输入 | 实时传感器锚定 | 用户打字或固定题库 |
| 调性 | 无厘头、可自嘲 | 偏严肃或泛娱乐 |
| 交互仪式 | 戳 LazyCat | 按钮 / 摇一摇 / 表单 |
| 离线能力 | 80+ 条模板库兜底 | 多数强依赖网络 |
| 配置成本 | 开箱即用（内置 DeepSeek Key） | 常需注册或自备 Key |

**差异点**：「传感器 + 废话」的组合较少见；多引擎降级保证弱网/超配额仍有体验。弱点是缺乏品牌与分发，依赖口碑与分享图传播。

---

## 商业/增长潜力

- **传播**：分享图 + 收藏适合轻社交裂变；内容具随机性与幽默感，适合短视频/表情包二次创作  
- **变现**：当前无广告/IAP；DeepSeek 按次计费，内置 Key + 日限额 50 次/设备控制成本  
- **留存**：收藏页提供轻度回访理由；**每日本地推送**（设置页可开关，默认 09:00）已上线 MVP；缺 streak 等机制  
- **规模瓶颈**：客户端密钥不可长期支撑大规模用户；需服务端代理或按用户令牌才能安全扩量

## 风险与技术债

| 风险 | 严重度 | 现状与缓解 |
|------|--------|------------|
| **客户端内置 DeepSeek API Key** | 高 | 密钥编译进 `DeepSeekConfig.builtInApiKey`，可被反编译提取并滥用；**缓解**：`DeepSeekUsageTracker` 每设备每自然日最多 50 次（本地时区、`SharedPreferences`），超限静默走模板库，用户无感知 |
| 本地限额可绕过 | 中 | 重装 App、清数据或改系统日期可重置计数；无服务端校验 |
| API 成本失控 | 中 | 日限额抑制单设备滥用；提取密钥后批量调用仍可能产生费用 |
| 传感器隐私感知 | 低–中 | DeepSeek 请求发送传感器摘要；设置页脚注已披露，缺首次授权说明 |
| Android / iOS parity | 中 | Android 无本地 MLX/苹果 AI；README 表格已说明，应用内引导不足 |
| 引擎 UI 与行为不一致 | 低 | 角标显示计划引擎，实际可能因配额/失败降级；易困惑 |
| 技术债 | 低 | `PreferredEngine` 与设置页引擎列表代码仍存在但未暴露；千问 `loadModel` 路径无用户入口 |

**生产前必做（安全）**：服务端代理 DeepSeek、短期令牌或按设备注册限额；密钥轮换与用量监控。

## 总评与一句话建议

**总评**：1.0.0 已达到可演示、可传播的 MVP 水位。核心闭环扎实，零配置 DeepSeek 改善了首次体验，文档与实现终于一致。主要短板从「叙事脱节」转为「增长基建缺失」与「内置密钥不可规模化」——后者是上线扩量前的硬门槛。

**一句话建议**：**在保持零摩擦体验的前提下，补 onboarding 与分享增长，并规划服务端代理替换内置密钥**——先让用户懂「戳猫会发生什么」，再让密钥与成本可控地支撑更多用户。
